# Deployment

Deploy the Vite frontend as a static site and the Express API as a Node 22.12+ web service. Configure the frontend build command `npm run build` and publish `dist/`. Configure the API working directory `server`, install with `npm install`, and start with `npm start`.

Set `VITE_API_BASE_URL` to the deployed API `/api/v1` URL. Set `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `PORT`, `CLIENT_URL`, exact `CORS_ORIGINS`, `NODE_ENV=production`, and `AUTH_COOKIE_SAME_SITE=Lax` on the API. Do not set Supabase credentials in frontend build variables. The API listens on `PORT` and exposes `/health`. Add the deployed frontend callback URL to Supabase Auth redirect settings. Use HTTPS and platform-managed secrets. Keep frontend and API under the same site where possible; if they are on different sites, use `AUTH_COOKIE_SAME_SITE=None` with HTTPS and test browser third-party cookie behavior. With default Vercel and Render hostnames, they are different sites, so cross-site cookies may be blocked by browser privacy controls; use custom subdomains under one registrable domain or a same-site API proxy for reliable sessions. `vercel.json` applies frontend security headers; narrow its CSP `connect-src` to the deployed API origin after choosing the hostname. If the frontend is hosted as a Render Static Site instead, configure the equivalent headers in the Render Dashboard.

Do not deploy until the SQL migration has been reviewed/applied, provider-specific build/start behavior is configured, auth redirects and CORS are tested, database backups/monitoring are enabled, and remaining unsupported modules are understood. Resend-based invitation and invoice email can be enabled with server environment variables. Payment recording is manual bookkeeping only; there is no card checkout, payment provider, or verified webhook integration. Client portal and subscription entitlement enforcement are not implemented. Validate the private Storage bucket policies in the target project before uploading business files.
